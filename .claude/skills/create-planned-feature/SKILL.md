Исполни этап плана из `.claude/current-plan.md`. Аргумент: `$ARGUMENTS` (пусто = первый этап со `Статус: [ ]`).

Состояние хранится только в `.claude/current-plan.md` (`Статус: [x]`) и в git. Память прошлой
сессии не нужна: план самодостаточен, поэтому `/clear` между этапами ничего не теряет.

## Шаг 1. Подготовка
1. Прочитай `.claude/current-plan.md` целиком. Файла нет → напиши
   «План не найден, запусти /plan-feature <описание>» и остановись.
2. Прочитай файлы из раздела «Контекст для чтения» плана (`CLAUDE.md` уже в контексте).
3. Выбери этап:
   - аргумент задан → этап с этим номером; если он `[x]` или N/A — спроси, точно ли повторять;
   - иначе → первый этап со `Статус: [ ]` (N/A пропускай);
   - незавершённых нет → напиши «Все этапы выполнены» и остановись.
4. Выполни `git status --short`. Есть незакоммиченные изменения вне `.claude/current-plan.md` →
   покажи их и спроси, что делать. Не продолжай без ответа.
5. Прочитай каждый файл из «Можно менять» этапа (если существует) перед правкой.

## Шаг 2. Реализация
- Выполняй «Шаги» этапа по порядку, буквально. Код из плана (типы, сигнатуры) вставляй как есть.
- Меняй ТОЛЬКО файлы из «Можно менять». Нужен другой файл → остановись и спроси.
- Не добавляй ничего сверх плана: ни рефакторинга, ни «улучшений», ни лишних комментариев.
- План неясен, противоречит коду или ADR → остановись, процитируй проблемное место,
  предложи 1–2 варианта. Не угадывай.
- Переиспользуй хелперы, указанные в плане; не создавай дубликаты.

## Шаг 3. Верификация
Запусти команды из «Верификации» этапа (обычно `npm run build`, `npm run lint`, с Этапа 2 — `npm test`).
- Этап 2: красными должны быть только тесты, перечисленные в плане как ожидаемо красные.
  `tsc -b` и lint — зелёные.
- Прочие этапы: всё зелёное.
- Ошибка → исправь в рамках белого списка. После 2 неудачных попыток остановись:
  покажи ошибку и что пробовал.
- Нельзя: отключать правила lint, `// @ts-ignore`, `any` ради зелёной сборки, `.skip` на тестах,
  правка тестов Этапа 2 под реализацию (кроме явной ошибки в тесте — тогда спроси).

## Шаг 4. Чек инвариантов
Источник правил — Product Invariants / UI Isolation / Gotchas в `CLAUDE.md` + «Чек инвариантов» этапа.
Проверяй сами файлы из «Можно менять» (не `git diff`: он не видит новые неотслеживаемые файлы).
Обязательные проверки (`<файлы>` — изменённые и новые файлы этапа):

1. Запись в поля хоста — пусто, кроме узлов внутри своего Shadow DOM:
   `grep -nE "\.value\s*=[^=]|execCommand|\.textContent\s*=[^=]|\.innerText\s*=[^=]|\.innerHTML\s*=[^=]" <файлы>`
2. Кнопки автоисправления — пусто:
   `grep -niE "fix all|apply|accept" <файлы>` (совпадения в комментариях/тестах на запрет — ок)
3. Оффсеты от LLM — якорение только через `indexOf` по `quote`:
   `grep -nE "offset|start|end" <файлы>` → каждое совпадение не должно приходить из ответа LLM.
4. `src/shared/types.ts` — только `type` / `interface` / `export type`, без `const`, `function`, `class`.
5. API-ключ вне background — пусто:
   `grep -rniE "api[_-]?key" src --include=*.ts --include=*.tsx | grep -v "src/background/"`
   (кроме типов в `types.ts`).
6. Service worker без состояния в модуле: в изменённых `src/background/*` нет изменяемых
   `let` на верхнем уровне и мутируемых `const` (Map/Set/массив/объект-кэш).

Плюс каждый пункт «Чек инвариантов» этапа. Нарушение → исправь до отчёта.

## Шаг 5. Отчёт и ожидание
Выведи кратко:
1. `Этап N — <название>`: что сделано (2–4 пункта).
2. `git diff --stat` + список новых файлов (`git status --short`).
3. Результат верификации (итоговые строки каждой команды).
4. Чек инвариантов: ✅ / ❌ по пунктам.
5. Сообщение коммита из плана.
6. Следующий шаг — по номеру СЛЕДУЮЩЕГО незавершённого этапа (не N/A):
   - Этап 1 или 2 → `Жду: commit / next / правки`
   - Этап 3 или 4 → `Жду: commit / next / правки. Рекомендую: commit → /clear → /create-planned-feature
     (свежий контекст: логика должна опираться на тесты на диске, а не на память сессии)`
   - больше нет → `Жду: commit / правки. Это последний этап.`

ОСТАНОВИСЬ. Не коммить без команды.

## Команды пользователя
- **commit** → `git add <файлы из «Можно менять» этапа>` (не `-A`, не `.`) +
  `git commit` с сообщением из плана; затем в `.claude/current-plan.md` замени `Статус: [ ]`
  этапа на `Статус: [x]`; покажи `git log --oneline -1` и остановись.
- **next** → то же, что commit, затем сразу начни следующий этап с Шага 1 п.3. Не переспрашивай:
  рекомендация про `/clear` уже дана в отчёте.
- **любые правки** → внеси их (в рамках белого списка), повтори Шаги 3–5.

`.claude/current-plan.md` в `.gitignore` — не добавляй его в коммит.
